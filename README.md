# ImmortalWrt-CI-XG-040G-MD-UBI

[简体中文](README_CN.md) | English

Cloud-built ImmortalWrt firmware for **Nokia XG-040G-MD** using the **Airoha AN7581 all-in-UBI layout**.

This project is intended for XG-040G-MD devices that have already been migrated to the mainline/OpenWrt U-Boot UBI layout, for example by completing a supported **MedveFlasher** installation.

## Target

- Source: `immortalwrt/immortalwrt`
- Branch: `master`
- Target: `airoha`
- Subtarget: `an7581`
- Device: `nokia_xg-040g-md-ubi`
- Upgrade image: `*-nokia_xg-040g-md-ubi-squashfs-sysupgrade.itb`

ImmortalWrt defines this device as an UBI variant with both the kernel and U-Boot environment stored in UBI and produces `sysupgrade.itb` as the normal upgrade image.

## Important safety warning

The firmware produced by this repository is **only** for the `nokia_xg-040g-md-ubi` layout.

Do **not** flash the generated `.itb` directly onto:

- stock Nokia firmware;
- the legacy `nokia_xg-040g-md` layout;
- a tcboot/factory layout that has not been migrated to `nokia_xg-040g-md-ubi`;
- a device whose board/layout cannot be positively identified.

Do not use `mtd write` to manually write this sysupgrade image, and do not overwrite BL2/FIP/preloader during a normal firmware upgrade.

## After MedveFlasher: how to flash this firmware

If MedveFlasher has completed successfully, its permanent OpenWrt system should already be bootable. This repository's `.itb` is then used as a **normal sysupgrade image**; you do not need to reinstall the bootloader.

### 1. Verify the router is already on the UBI layout

SSH into the router and run:

```sh
ubus call system board
```

Confirm the board is the XG-040G-MD **UBI** variant. You should see a board name corresponding to:

```text
nokia,xg-040g-md-ubi
```

For additional verification:

```sh
cat /proc/mtd
ubinfo -a
```

If the device still identifies as the legacy/non-UBI profile, stop here and do not flash this image.

### 2. Download the build artifact

Open the successful GitHub Actions run and download:

```text
ImmortalWrt-XG-040G-MD-UBI
```

Extract the archive. It should contain an image similar to:

```text
immortalwrt-airoha-an7581-nokia_xg-040g-md-ubi-squashfs-sysupgrade.itb
```

and:

```text
SHA256SUMS
```

Verify the checksum on your computer before uploading the image.

### 3. Upload the `.itb` to the router

Example:

```sh
scp immortalwrt-*-nokia_xg-040g-md-ubi-squashfs-sysupgrade.itb \
  root@192.168.1.1:/tmp/firmware.itb
```

Then connect by SSH:

```sh
ssh root@192.168.1.1
```

### 4. Test image compatibility before flashing

Run:

```sh
sysupgrade -T /tmp/firmware.itb
```

Only continue if the image validation succeeds. If validation reports an incompatible device/image, stop and do not force the upgrade.

### 5. First upgrade from the MedveFlasher-installed system

For the first switch from MedveFlasher's bundled permanent OpenWrt to this ImmortalWrt build, a clean configuration is recommended:

```sh
sysupgrade -v -n /tmp/firmware.itb
```

`-n` means **do not keep the existing configuration**. This avoids carrying settings across different firmware build roots.

The router will write the firmware and reboot automatically. Do not remove power while the upgrade is in progress.

### 6. Later upgrades from this same CI project

For subsequent upgrades generated by this repository, configuration can normally be retained:

```sh
sysupgrade -v /tmp/firmware.itb
```

A clean upgrade with `-n` is still recommended after major changes, when changing package sets substantially, or when troubleshooting unexplained behavior.

## Build

Open **Actions → Build ImmortalWrt XG-040G-MD UBI → Run workflow**.

The workflow:

1. clones current ImmortalWrt `master`;
2. installs feeds;
3. applies `config/xg040g-md-ubi.config`;
4. runs `make defconfig`;
5. builds the firmware;
6. uploads only the XG-040G-MD UBI sysupgrade image and checksums.

## Customization

Add package selections to `config/xg040g-md-ubi.config`.

Use `scripts/customize.sh` for source-tree changes that cannot be expressed as normal Kconfig package selections.

The initial configuration intentionally stays close to upstream ImmortalWrt so that flash-layout/NAND issues are not mixed with unrelated third-party package changes.
